Technical readiness report · 10 July 2026

GKFEED as a Telegram Mini App

The existing React site is a sound starting point and can be displayed inside Telegram, but it needs targeted integration work before it behaves like a production Telegram Mini App.

Verdict: update required

Suitable for an early in-Telegram preview now. Telegram authentication, platform integration, adaptive layout, deployment, and bot configuration are still required for a proper release.

What the code supports today

GKFEED is already a responsive Vite and React single-page application. Its Nginx configuration supports client-side routes, and the API defaults to a public HTTPS endpoint. Those are useful foundations, but the application currently has no Telegram-specific runtime or identity flow.

Web application

Ready

React 19, Vite, responsive CSS, and SPA route fallback provide a usable embedded web foundation.

Telegram SDK

Missing

index.html does not load Telegram's Web App script, so window.Telegram.WebApp and its platform APIs are unavailable.

Authentication

Replace

The browser stores a username and password in localStorage and sends Basic Authentication. A Mini App should send Telegram initData to the backend for server-side validation and session creation.

Telegram UI behavior

Missing

The app does not currently call ready(), use Telegram's Back Button, respond to theme changes, or account for Telegram viewport and safe-area values.

Routing

Ready

BrowserRouter can work because Nginx falls back to index.html. Bot launch URLs should still be tested for direct navigation and refresh behavior.

Deployment

Verify

The container listens on port 80. Production must expose the frontend through a public HTTPS URL, commonly via a reverse proxy or CDN.

Bot configuration

Required

A Telegram bot must be configured to launch the deployed URL through BotFather or the Bot API, using the chosen menu, main-app, keyboard, or direct-link entry point.

Minimum implementation path

Add a Telegram adapter

Load the official Web App script, expose typed access to window.Telegram.WebApp, call ready(), and preserve normal-browser operation when Telegram is absent.

Implement trusted identity

Send raw initData to the API. Validate its signature and freshness on the server, then issue the application's own session. Never trust initDataUnsafe for authorization.

Adapt the interface

Apply Telegram theme values where appropriate, support safe-area insets and changing viewport height, and connect navigation to Telegram's Back Button.

Deploy and register

Publish the built app at a stable HTTPS origin, configure the bot launch URL, and verify launch paths on Telegram for Android, iOS, and Desktop.

Important backend dependency

The frontend cannot complete secure Telegram login by itself. The API must validate Telegram's signed launch payload before associating a Telegram user with a GKFEED account. Until that endpoint exists, the current username/password flow can remain as a browser fallback, but it should not be presented as Telegram-native authentication.
