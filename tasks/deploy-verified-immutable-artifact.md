# Деплоить проверенный immutable-артефакт

Status: proposed. Текущие незакоммиченные изменения добавляют сборку и smoke-тест образа, но production по-прежнему выполняет `git pull` и локальную сборку.

Priority: P2

## Проблема

CI проверяет checkout конкретного запуска, затем production-сервер выполняет `git pull`. Если ветка обновилась между этими действиями, сервер может собрать другой, непроверенный коммит.

## Что сделать

- После проверок собирать Docker-образ в CI.
- Маркировать образ commit SHA и публиковать его в registry.
- Развёртывать образ по digest или точному SHA.
- Добавить health-check после запуска и автоматический отказ при неуспешной проверке.
- Хранить предыдущий digest для быстрого отката.
- Убрать сборку production-приложения из `make update`.

## Критерии приёмки

- SHA развёрнутого приложения совпадает с SHA проверенного workflow.
- Production-сервер не собирает приложение из рабочей копии Git.
- Повторный деплой использует тот же образ.
- Предыдущую версию можно вернуть без новой сборки.
- Неуспешный health-check завершает деплой ошибкой и не оставляет неисправную версию активной.
