# Добавить структурированную диагностику BFF

Status: proposed

Priority: P2

## Проблема

Неожиданные исключения преобразуются в публичный `internal_error`, но HTTP-обработчик не сохраняет исходную причину. По production-ответу нельзя восстановить маршрут запроса, длительность и место сбоя.

## Что сделать

- Присваивать каждому запросу request ID.
- Внедрить структурированный logger через composition root.
- Записывать маршрут, HTTP-статус, длительность и внутренний код ошибки.
- Записывать попадания в кеш, ожидание очереди, отмены, rate limit и upstream timeout.
- Исключить credentials, `Authorization` и query с пользовательскими URL из логов.

## Критерии приёмки

- Каждому ответу `500` соответствует серверная запись с request ID и исходной ошибкой.
- BFF возвращает request ID клиенту в заголовке ответа.
- Логи не содержат пароли и заголовок `Authorization`.
- Ожидаемые ошибки клиента отличаются от внутренних сбоев.
- Logger можно подменить в unit-тестах.
