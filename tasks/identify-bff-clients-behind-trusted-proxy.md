# Корректно определять клиентов BFF за reverse proxy

Status: proposed

Priority: P1 при работе за reverse proxy, иначе P2

## Проблема

Лимитер использует `request.socket.remoteAddress` как client ID. За reverse proxy это может быть один адрес для всех пользователей. Тогда пользователи делят ограничения на активные, ожидающие и минутные запросы.

## Что сделать

- Описать production-схему сети и список доверенных прокси.
- Добавить конфигурацию trusted proxy через environment.
- Читать forwarded-адрес только для соединений от доверенного прокси.
- Нормализовать IPv4, IPv6 и IPv4-mapped IPv6.
- Определить стабильный fallback, если клиентский адрес получить нельзя.

## Критерии приёмки

- Разные клиенты за доверенным прокси получают независимые лимиты.
- BFF игнорирует поддельный `X-Forwarded-For` от прямого клиента.
- BFF игнорирует forwarded-заголовки от недоверенного прокси.
- Поведение прямого соединения, доверенного и недоверенного прокси покрыто тестами.
