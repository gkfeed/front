# Настроить TTL BFF-кеша по типу ресурса

Status: proposed

Priority: P2

## Проблема

BFF использует единый TTL 60 секунд. UI запрашивает обновление live-матча каждые 30 секунд, поэтому часть обновлений возвращает прежний снимок.

## Что сделать

- Определить требования к свежести каждого BFF-маршрута.
- Хранить cache policy рядом с описанием маршрута или use case.
- Назначить короткий TTL live-данным и отдельный TTL обычным превью и статьям.
- Явно отметить ресурсы, результат которых кешировать нельзя.
- Сохранить объединение одновременных запросов для ресурсов без кеширования результата.

## Критерии приёмки

- Live-данные обновляются с частотой, заявленной в UI.
- Cache policy каждого маршрута объявлена в одном месте.
- Тесты проверяют разные TTL, истечение записей и отключённое кеширование.
- Одновременные одинаковые запросы по-прежнему используют одну upstream-загрузку.
