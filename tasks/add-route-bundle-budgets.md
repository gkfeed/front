# Добавить bundle budgets для маршрутов

Status: proposed

Priority: P2

## Проблема

Текущая проверка ограничивает только `index-*.js` и `index-*.css`. Чанки страниц и медиаплеера не входят в budget. Поэтому сборка проходит с CSS-чанком около 70 КБ и HLS-чанком около 574 КБ без сжатия.

HLS загружается динамически, поэтому для него нужен отдельный лимит. Его размер не должен блокировать стартовую загрузку приложения.

## Что сделать

- Получать из Vite manifest ресурсы, связанные с каждым маршрутом.
- Проверять суммарный размер JS и CSS начальной загрузки и ленивых маршрутов.
- Использовать gzip или Brotli-размер как основной показатель и выводить исходный размер для диагностики.
- Проверять HLS отдельным лимитом.
- Выводить в CI имя ресурса, фактический размер, лимит и величину превышения.
- Описать в README порядок обоснованного изменения лимитов.

## Предлагаемые стартовые лимиты

- Начальная загрузка: не более 120 КБ gzip JS.
- Reader: не более 30 КБ gzip JS.
- CSS одного маршрута: не более 15 КБ gzip.
- HLS: не более 190 КБ gzip.

Перед фиксацией лимитов нужно проверить состав маршрутов по Vite manifest и исключить двойной подсчёт общих чанков.

## Критерии приёмки

- Проверка учитывает общие и ленивые чанки каждого маршрута.
- Один общий чанк не суммируется дважды в пределах маршрута.
- Превышение лимита завершает сборку с ошибкой и понятным сообщением.
- HLS не входит в budget начальной загрузки и проверяется отдельно.
- Текущие размеры проходят выбранные и документированные лимиты.
