# Сжимать статические ресурсы в production

Status: proposed

Priority: P2

## Проблема

Встроенный Node.js-сервер отдаёт JS и CSS без Brotli или gzip. Основной JS текущей production-сборки занимает около 324 КБ без сжатия и около 102 КБ в gzip.

Неизвестно, сжимает ли ответы внешний production proxy. Это нужно проверить до изменения приложения.

## Что сделать

- Проверить заголовки JS и CSS в production при `Accept-Encoding: br, gzip`.
- Если внешний proxy не сжимает ответы, включить Brotli или gzip на proxy либо выдавать предварительно сжатые файлы из Node.js-сервера.
- Добавить `Vary: Accept-Encoding` для ресурсов с согласованием кодировки.
- Сохранить правильные `Content-Type`, `Content-Length` и cache policy.

## Критерии приёмки

- Production-запрос JS или CSS с `Accept-Encoding: br, gzip` получает сжатый ответ.
- Клиент без поддержки сжатия получает исходный ресурс.
- Браузер загружает и выполняет сжатый JS без ошибок.
- Хешированные ресурсы сохраняют `Cache-Control: public, max-age=31536000, immutable`.
- Интеграционный тест проверяет сжатый и несжатый ответы.
